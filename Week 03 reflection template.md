## Implementation Reflection

5. Why did you decide to split your Feature Set into multiple GitHub issues or use a single issue?

Answer: 
I used a single GitHub issue because the work focused on one feature area, the Schedules feature. Keeping everything in one issue made it easier to track related tasks such as creating the schema, model, controller, API route and Swagger documentation. Since all of these changes were closely related, a single issue provided a clear implementation path.
